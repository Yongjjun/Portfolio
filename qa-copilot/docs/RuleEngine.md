# QA Rule Engine

## Rule Definition

| Rule | Trigger | Selection Criteria | Exclusion Criteria |
|---|---|---|---|
| **Validation** | 사용자 입력 필드가 존재 | 입력값의 형식/필수 여부 자체가 요구사항의 핵심인 경우 | 단순히 숫자/문자 값이 언급된 것만으로 선택하지 않음 |
| **Boundary Value** | 최소/최대/범위 제한 존재 | 명시적인 경계값 검증이 핵심인 경우 | 단순한 조건/제한이라는 이유만으로 선택하지 않음 |
| **Equivalence Partition** | 유효/무효 그룹 구분 가능 | 입력값 그룹을 나누어 대표값 테스트가 필요한 경우 | 단순히 정상/비정상 입력이 가능하다는 이유만으로 선택하지 않음 |
| **Negative Test** | 예외/잘못된 입력 가능 | 잘못된 입력이나 실패 상황에 대한 시스템 반응이 요구사항에 포함된 경우 | 단순히 "제한"이나 "불가"가 있다는 이유만으로 선택하지 않음 |
| **Business Rule** | 정책/업무 규칙 존재 | 서비스 정책이나 업무 조건 자체를 검증하는 것이 핵심인 경우 | 단순한 입력 검증이나 UI 동작만으로 선택하지 않음 |
| **State Transition** | 상태 변경 존재 | 명확한 상태 변화 또는 상태 간 이동을 검증해야 하는 경우 | 단순히 데이터가 변경되었다는 이유만으로 선택하지 않음 |
| **Regression** | 기존 기능 변경 | 기존 기능에 대한 영향/회귀 검증이 요구사항에 명시되거나 명확한 경우 | 단순히 "수정/변경"이라는 단어만으로 선택하지 않음 |
| **Platform** | 여러 플랫폼 존재 | 플랫폼별 동작 차이 또는 동일성 검증이 요구사항의 핵심인 경우 | 플랫폼명이 언급되었더라도 플랫폼 차이가 검증 대상이 아니면 선택하지 않음 |
| **Accessibility** | 접근성 요구 존재 | 접근성 기능/사용성 보장이 명시된 경우 | 화면 크기나 다양한 환경만으로 접근성을 선택하지 않음 |
| **Security** | 인증/권한/민감정보 | 인증·권한·개인정보 보호 자체가 검증 대상인 경우 | 로그인/개인정보라는 단어만으로 보안 Rule을 자동 선택하지 않음 |

## Rule Selection Principle

QA Rule은 단순히 적용 가능한 모든 테스트 기법을 나열하는 것이 아니라,
해당 요구사항의 **핵심 검증 목적**을 기준으로 선택한다.

1. 요구사항의 핵심 검증 목적을 기준으로 Rule을 선택한다.
2. 단순히 적용 가능한 테스트 기법이라는 이유만으로 Rule을 추가하지 않는다.
3. 하나의 요구사항에 여러 Rule이 명확하게 필요한 경우 복수 Rule을 선택한다.
4. 요구사항에 직접적인 근거가 없는 Rule은 선택하지 않는다.
5. 다른 Rule과 연관될 수 있다는 이유만으로 Validation, Negative Test 등을 자동으로 추가하지 않는다.
6. 수치나 범위가 명시된 경우 Boundary Value를 고려한다.
7. 정책이나 업무 조건이 핵심인 경우 Business Rule을 고려한다.
8. 상태 간 이동이 핵심인 경우 State Transition을 고려한다.
9. 여러 플랫폼 간 동작 차이 또는 동일성이 핵심인 경우 Platform을 선택한다.
10. 인증, 권한 또는 개인정보 보호가 핵심인 경우 Security를 선택한다.

## Rule Selection Reference

| Requirement Pattern | Recommended Rule |
|---|---|
| 최소/최대/범위 등 명시적인 경계 조건 | Boundary Value |
| 입력 형식 또는 필수 여부 검증 | Validation |
| 유효/무효 그룹을 나누는 것이 핵심 | Equivalence Partition |
| 잘못된 입력이나 실패 상황에 대한 처리가 핵심 | Negative Test |
| 서비스 정책이나 업무 조건이 핵심 | Business Rule |
| 상태 간 이동이나 상태 변화가 핵심 | State Transition |
| 기존 기능에 대한 영향 검증이 핵심 | Regression |
| 플랫폼별 동작 차이 또는 동일성 검증이 핵심 | Platform |
| 접근성 요구사항 검증이 핵심 | Accessibility |
| 인증/권한/개인정보 보호가 핵심 | Security |
